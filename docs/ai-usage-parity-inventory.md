## 9. Prioritized gap list

Follow-up issues: gap 1 fixed with #394; gap 2 is #449; gap 5 is #450; gap 7 is #451; gap 9 is #452; gaps 3 and 8 are #453; gaps 4, 6 and 10 are #454.

1. **Agent and MCP cannot narrow provider selection (M, Cockpit).** `AIUsageViewModel.usage(from:)` calls `session.perform("ai-usage")` with no provider argument (`tuning/Sources/SymCockpitUI/AIUsageViewModel.swift:72-80`), `run_spec` hardcodes `provider: None` (`crates/symcockpit/src/mcp.rs:502`), and `usage_report` then selects the full catalog (`crates/symcockpit-core/src/ai_usage.rs:416-420`). Disabled providers are still discovered by Brain and their credential keys are still placed in the child environment (`crates/symcockpit-core/src/ai_usage.rs:180-191`). Acceptance check: with one provider enabled, an injected fake runner records exactly `symbrain usage --output json --providers <that-id>` and the child environment contains a `symvault://` reference only for selected API-key providers; no disabled provider ID or reference appears in arguments, environment, result rows, UI, cache or HTTP output.

2. **Preference changes cause a whole enabled-set refresh (S, Cockpit).** The callback installed at `tuning/Sources/SymCockpitUI/AIUsageViewModel.swift:104-112` calls `refreshNow()` with no provider ID whenever provider selection or any history-consent preference changes. That fans out to every enabled provider through the all-provider agent call. Acceptance check: changing a display-only preference produces zero usage fetches; changing one provider's consent or enabled state produces a fetch scoped to that provider only, while the existing queued per-provider behavior in `AIUsageQueuedRefreshTests.swift` still passes.

3. **No multi-account or source-variant model (L, Cockpit plus Brain).** Cockpit rows are keyed by provider ID (`tuning/Sources/SymCockpitCore/AIUsage.swift:49-84`), so two accounts of the same provider cannot coexist, and there is no equivalent of OpenUsage's `Account.cardID`, GHE.com domain or organization billing variant (`Sources/OpenUsage/Models/Account.swift:81-102`). Acceptance check: two accounts of one provider yield two distinguishable rows with independent pin, hide, refresh and cache entries; org billing and GHE variants are represented without colliding with personal accounts.

4. **No provider-reported daily spend and token histories (L, Cockpit plus Brain).** Cockpit's history path accepts only local, unattributed records for grok, opencode, claude and codex (`tuning/Sources/SymCockpitCore/AIUsageLocalRecordedSpend.swift:39-46`), while OpenUsage reads provider reports for ChatGPT, Cursor, Ollama and OpenRouter (`Sources/OpenUsage/Providers/Codex/CodexHistorySource.swift:31-64`). Acceptance check: a consented history row shows provider-reported spend and tokens with explicit provenance, missing days are absent rather than zero, and disabling consent removes the row from UI, CLI, API and cache.

5. **No Priority-based menu bar and alert behavior (M, Cockpit).** Cockpit's status item is a joined list of up to four stars (`tuning/Sources/SymCockpitUI/AIUsageViewModel.swift:281-310`) with no running-out ordering, overflow count, thresholds or notifications as implemented in OpenUsage (`Sources/OpenUsage/Models/MenuBarContent.swift:30-47`, `Sources/OpenUsage/Stores/QuotaNotificationEvaluator.swift:16-67`). Acceptance check: with warning and critical thresholds configured, the strip shows the configured number of most urgent limits plus an overflow count; pinned, used-up and use-it-or-lose-it sections follow documented order; alert switches respect per-account consent and macOS notification permission.

6. **No rate-limit reset claim flow (L, Cockpit plus Brain).** OpenUsage builds claimable reset items and spends a chosen reset after confirmation (`Sources/OpenUsage/Providers/AccountProviderRuntime.swift:79-103`). Cockpit only renders meters. Acceptance check: a risky plan is recorded, no reset is spent before confirmation, and the confirmation names the exact account and limit family.

## 10. Things that could not be verified

- Live provider behavior was not exercised. No provider accounts, tokens or keys were available and no provider API calls were made. Claims about what a provider currently reports come from source and documentation at the inspected SHA, not from a live fetch.
- Symaira Brain was not inspected. Its repository was not part of this task. Provider fetch, auth, reset claims and history generation are assigned to Brain by the product boundary, so this inventory cannot confirm whether a capability exists there. Status `out-of-scope-Brain` does not mean absent from Brain.
- Cockpit was inspected statically. No build, test, GUI interaction or agent process was run because the repository is read-only for this task. The issue comment's phrase "presentation-only preference change refetches all enabled providers" was not independently reproduced. The code confirms that selection and history-consent callbacks call `refreshNow()` with no provider argument, but no pin-only or layout-only refetch path was found in the inspected code.
- OpenUsage feature descriptions were checked against implementation files where cited, but notifications, OAuth scope behavior, reset redemption and screen-capture detection were not run. Their status here is source behavior at commit `53f70b396698656cb5e1e3f59c40d1b86d6b5296`, not deployed behavior.
- Compatibility with an installed `symbrain` binary was not checked. Cockpit's minimum contract is documented in code (`tuning/Sources/SymCockpitCore/SymBrainUsageClient.swift:286-289`), but no installed version was queried.
- The mapping between Cockpit IDs `kimi`, `moonshot` and `nous` and OpenUsage's provider list could not be established from either tree. They are counted as catalog-only entries, not as certified provider support.
- OpenUsage's hub documentation file `docs/cliproxyapi.md` was listed in the tree but not read in full. Hub behavior cited here comes from `docs/providers.md`, `docs/accounts.md`, `Sources/OpenUsage/Models/Account.swift` and `Sources/OpenUsage/Providers/ProviderCatalog.swift`.
